# 数据、缺口与结论规则

## 证据分层

| 级别 | 允许用途 | 例子与限制 |
|---|---|---|
| **A 官方披露** | 经营事实、指标口径 | SEC、Duolingo IR、股东信；管理层对原因的解释仍应标为“公司认为”。 |
| **B 可靠外部** | 市场与竞品佐证 | 有可检查方法、日期与样本的研究或平台数据；先查使用许可和估算口径。 |
| **C Proxy / VOC** | 方向性假设 | 搜索、网站流量、排名、公开评论；不能替代 App 内部用户行为或代表所有用户。 |
| **D Synthetic / 假设** | 方法演示、敏感度 | 清晰标注生成规则与参数；绝不并入真实经营结果或称为 Duolingo 实验结果。 |

每条数据最少记录：来源 URL、发布与覆盖时间、访问日期、指标定义、单位、粒度、地理/用户范围、许可/再分发限制、计算转换和局限。核心经营数字优先核对官方原表；冲突或口径变化才继续追查。市场估算必须保留方法说明。原始第三方内容不因网页可访问就默认可再分发。

## 缺失数据的处理顺序

1. **判定是否为决策必需**：不影响本轮选择的缺口直接放入后续清单。
2. **找同口径公开来源**：优先官方，一次来源核对；关键冲突才做第二轮核对。
3. **仍缺失则选降级**：公开 Proxy 只能支持方向；区间/情景只回答阈值；无法替代的内部量留空并写明获取需求。
4. **明确不可识别的结论**：例如无法从公司 DAU 推出 Video Call 的留存提升。不要插值、猜测、套用别家 uplift，亦不以模拟数据填补真实效果。
5. **继续业务流程**：缺口写入决策卡的风险或实验数据需求；除非它让当前决策完全无法表述，不因寻找完美数据而卡住项目。

| 常见缺口 | 本项目做法 | 可写的结论 |
|---|---|---|
| Video Call 采用率、说词量分群 | 记录官方定性披露；制定未来事件与分群字段 | 覆盖/使用方向的公司陈述，不写精确用户级效果。 |
| D7/D30、续费、转化、成本 | 定义实验指标和所需埋点；量化模型用明确假设区间 | 达到盈亏平衡需要的 uplift/成本条件。 |
| 用户访谈与代表性样本 | 公开 VOC 做探索性编码，注明自选样本偏差 | 待验证的痛点与细分人群假设。 |
| 竞品真实订阅/流量 | 官方价格与功能截图优先，估算型平台数据标 B/C | 方向性定位，不写精确市场份额。 |

## 结论标记

- **观察事实**：可直接追溯到原始披露或复现计算。
- **管理层归因**：公司陈述的解释，不等于外部分析证明因果。
- **三角佐证**：多来源方向一致，仍非随机实验。
- **情景结果**：模型条件成立时的计算结果，不是预测。
- **模拟演示**：只证明方法运行，不证明产品效果。

公开公司级指标与功能上线时间并列时，不写“Video Call 导致 DAU 增长”。真实 A/B 只有在取得真实随机化、分组和结果数据后才能做效果估计与显著性声明。

## Stage4 v2补强后的当前约束

依据用户要求，Stage4正式交付不使用无实证依据的D经济数值、任意三情景/扫描域、固定试用额度或美元门槛。未知保持null，采用直接双臂全员核算、符号盈亏平衡/敏感度与具体缺口。v1演示仅历史审计，排除正式包。标价无同SKU/期限/方案不得配对，配对价格也不充当净贡献；完成者学习信号不能填经营参数。当前方法及状态以`quant/evidence_assumptions.md`和`docs/STAGE_STATUS.md`为准。
