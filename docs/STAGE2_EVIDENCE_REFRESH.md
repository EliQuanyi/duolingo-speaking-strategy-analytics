# Stage 2.1 — 用户证据补强执行卡

本执行卡的 VOC、竞品、市场逻辑链与收束判据，按 [`STAGE2_REINFORCEMENT_STANDARD.md`](STAGE2_REINFORCEMENT_STANDARD.md) 细化执行；当前 298 条用户提供样本的接收和未核验项见 [`STAGE2_INPUT_INTAKE.md`](STAGE2_INPUT_INTAKE.md)。

## 目的与边界

回答同一个问题：哪些 Speaking / Video Call 体验值得优先验证，现有公开证据能支持到什么程度？以 **Duolingo Video Call 直接体验**为核心；一般 Speaking 和竞品体验分别标记，只作机制或替代选择的佐证。保留首轮 33 条 VOC 的历史记录，不把 77 行主题汇总算作新增样本，不用公开评论估计功能留存或收入效果。

## 可并行的三个工作包

| 工作包 | 任务 | 交接物 |
|---|---|---|
| A 来源与工具 | 核对 Google Play、App Store、Reddit 等平台的可用范围；先审 GitHub 项目的许可证、维护、字段、采样限制，再选择采集方式；必要时补视频评论等独立来源。 | `market/source_access_review.md`：候选来源、可取字段、覆盖与限制、试采结论。 |
| B 采集与质量 | 每个拟用平台先小量试采，估计 Video Call 相关命中率；随后按明确的时间、产品和采样规则扩充。记录原始 ID/URL、平台、产品、发表日期或未知、采集日期、语言/地区（若有）、采样方式；去重并抽核来源与分类。一般评论样本和关键词定向样本分开。 | `market/voc_sample_log_v2.csv` 与 `market/voc_quality_review.md`：可追溯样本、采样与去重说明、直接相关数量及抽核结果。 |
| C 产品决策审阅 | 复核主题编码与反例，检查不同平台是否给出一致或相反信号；将最多 3 条发现连接到目标用户、产品机制和下一轮实验。 | `market/stage2_decision_memo.md`：一页决策摘要，含发现、直接证据、局限、实验优先级。 |

A 与 B 的试采准备可以并行；扩大采集依据试采结果；C 在有首批可核验样本后启动。各工作包只改自己的交接物，由阶段负责人整合总纲和状态，避免并行覆盖。

## 数量目标与唯一收束点

争取 **至少 1,000 条去重的原始候选记录**；受平台限制或相关命中率约束时，以百级直接相关样本作为降级目标，并如实说明实际数量和原因。分别报告采集总量、去重后数量、直接相关数量；跨产品、跨平台不混成一个满意度或需求比例。指标字典是定义，主题汇总是派生计数，均不算新增观测。

阶段只做一次决策审阅：① 内容是否紧扣 Video Call 扩张问题；② 来源、口径、样本结构与原始记录是否足以支撑所写结论；③ 能否给 Stage 3/4 提供具体的用户细分、体验风险或实验假设。达到这三点即停止扩展并交接；不足则降低结论强度，指出一个最重要的剩余缺口。不得为凑数量、追求形式完整或远期用户预测继续搜集。
