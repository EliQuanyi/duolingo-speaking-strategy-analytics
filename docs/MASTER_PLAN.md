# 总纲与主计划：Duolingo AI Speaking / Video Call

## 一、项目北极星

**唯一主决策**：Duolingo 是否值得继续扩大 AI Speaking / Video Call 的覆盖与投入；如果值得，下一轮应优先验证哪类用户、市场和订阅权益配置？

本项目以外部分析者身份提供决策支持，展示三种能力如何连接：**市场调研发现需求与替代选择 → 数据分析诊断真实经营变化 → 量化分析比较机会、成本和阈值 → 设计对照实验验证 → 形成条件性决策**。重点是市场、经营与量化；多年 DAU 点预测仅在确有决策需要时作为附录。

所有工作必须回答下列四问中的至少一问，并最终回到主决策：

1. **Market**：口语练习需求对哪些用户足够重要，现有替代品留下什么空缺？
2. **Product**：Video Call 的具体机制如何改变口语行为与学习价值？哪些环节已有证据？
3. **Growth**：口语体验改善是否可能影响参与度与留存？公开经营表现能支持到什么程度？
4. **Monetization**：Max、Super、有限免费试用中，哪种配置在收益、成本和体验间最值得测试？

## 二、完整业务闭环

```text
公司战略目标（Teach Better / Grow Users / 订阅价值）
  → 市场与用户问题（需求、细分、竞品、VOC）
  → 产品价值链（问题 → 功能 → 行为 → 学习价值 → 业务结果假设）
  → KPI 与证据系统（定义、来源、可得性、缺口）
  → 经营现状（公开趋势、结构、对照）
  → Driver 诊断（直接证据 / 多源支持 / 待验证假设）
  → 机会量化（情景、敏感度、盈亏平衡）
  → 策略选项（Max / Super / 有限免费试用）
  → 对照实验预案（处理组、对照组、主要指标、护栏、决策规则）
  → 决策卡（Scale / Iterate / Stop，或先做试验）
  → 上线监控与异常触发 → 复盘 → 下一轮假设
```

这是**业务逻辑顺序**。实际执行时先做一次轻量的来源与口径治理（Stage 1），再进行市场采样（Stage 2），以免研究途中反复争论数据是否可用。项目取得不到内部实验数据时，闭环的可完成部分是**可审查的试验方案、条件性决策和监控设计**；不得展示虚构的实际上线、实验 uplift 或复盘结果。

### 各板块如何交接

| 业务板块 | 必须回答 | 交给下一板块的东西 | 不应越界 |
|---|---|---|---|
| 战略简报 | 公司为何现在关注 Speaking，管理层要选什么？ | 单一决策、目标人群候选、期限、关键未知 | 扩成全公司或整个语言学习行业研究 |
| 市场 / 用户 / 竞品 / VOC | 谁有痛点、替代方案是什么、证据强弱如何？ | 最多 3–5 条洞察及可测假设 | 将自选评论当代表性调查；堆砌 TAM |
| 产品价值 | Video Call 通过什么行为机制创造价值？ | 问题 → 功能 → 行为 → 学习 → 经营的因果假设图 | 把留存和收入提升写成已证实事实 |
| KPI / 数据 | 哪些指标能检验机制，哪些公开可得？ | 指标树、字典、来源表、缺口与降级方案 | 为填表伪造功能级数据 |
| 经营诊断 | 用户、订阅、产品推进、市场信号发生什么？ | 可复现趋势、可比口径、异常与替代解释 | 用公司总量变化归因于单个功能 |
| Driver / Quant | 哪些变化最值得关注、达到什么效果才划算？ | 证据等级、2–3 个关键 Driver、区间与盈亏平衡阈值 | 把敏感度当长期预测或因果估计 |
| 策略 / 实验 | 哪个选项先试、如何与对照组比较？ | 方案比较、预设 primary KPI、护栏和决策规则 | 看完结果再改成功标准；声称没有做过的实验 |
| 决策 / 监控 / 复盘 | 在什么条件下扩大、迭代或停止？ | 决策卡、指标触发器、下一轮假设 | 把规划中的 Dashboard 当真实上线监控 |

### 指标与证据骨架

- **学习与行为**：口语练习次数、主动说词量、课程完成；除官方定性披露外，多数需要内部事件数据。
- **参与与留存**：DAU、MAU、DAU/MAU、CURR；D7/D30 和用户分群留存只有数据可得时才分析。`Sustainable Active Learners` 可作为本项目的分析概念，**不是已核实的 Duolingo 官方 North Star**。
- **商业与成本**：付费订阅者、bookings、revenue、试用/转化/续费、AI 推理成本；公开指标与内部指标分列。
- **护栏**：学习完成率、投诉、取消、免费用户参与度、推理成本。任何建议均需同时说明预期收益和可能损害。
- **证据标签**：观察事实、管理层归因、多源支持、假设、情景、模拟；详细使用规则见 `DATA_POLICY.md`。

## 三、12 个业务板块与 7 个执行阶段

原方案的 12 个业务板块保持完整；仓库用 7 个较小的执行阶段交付，避免一次完成全部流程。以下映射是固定导航，不因途中出现新资料而随意增删板块。

| 原业务板块 | 本仓库执行阶段 | 收束物 |
|---|---|---|
| 01 Strategic Brief | Stage 0 | `DECISION_BRIEF.md` |
| 02 Market & User Research；03 Product Value Diagnosis | Stage 2 | 市场洞察、VOC 编码、产品价值链 |
| 04 KPI & Data System | Stage 1 | KPI 树、指标字典、来源与缺口矩阵 |
| 05 Business Health；06 Driver Diagnosis | Stage 3 | 经营复盘、Driver 证据分级 |
| 07 Opportunity Sizing；08 Strategy Design | Stage 4 | 机会模型、最多三个可比较的策略选项 |
| 09 Experiment Design；10 Decision Review | Stage 5 | 预设实验方案、决策卡 |
| 11 Monitoring；12 Retrospective | Stage 6 | 监控设计、管理层报告、已实际完成工作的复盘 |

最终作品固定为六类：**Executive Decision Book、可复现分析数据包、Quant Model、Experiment Plan 与决策卡、最多两页监控视图、Reusable SOP 与复盘**。每阶段**具体文件名和格式**以 `docs/DELIVERABLES.md` 为唯一清单。市场研究和经营诊断进入 Decision Book，其明细作为可核查附录。作品应能让读者追溯“市场证据 → 经营诊断 → 量化门槛 → 优先行动 → 验证规则”，并从图表追到数据表、计算方法与原始来源。

## 四、执行约束

每阶段只回答一个问题。交付物达到 Gate 即收束；新线索先写入 `docs/STAGE_STATUS.md` 的候选待办，不在当前阶段无限展开。每个结论都写明“发现 → 证据 → 商业含义 → 对决策的影响 → 未知项”。可公开分析的事实与只可设计的内部实验必须分开。

| 阶段 | 核心问题 | 最小交付物 | 工作上限与通过门槛 |
|---|---|---|---|
| **0 决策与范围** | 到底要做什么决定？ | `DECISION_BRIEF.md` | 1 个主决策、4 个业务问题、最多 3 个候选策略、数据边界清楚。**已通过。** |
| **1 证据与 KPI** | 哪些数字可用、口径是什么？ | 来源登记、指标字典、数据可得性矩阵、拟交付数据表的字段与粒度清单 | 优先 8–12 个核心指标；每个有来源、时期、单位、定义与限制。关键缺口按 `DATA_POLICY.md` 分类并指定降级方法。公开资料能支撑后续公司级趋势，才进入阶段 2。 |
| **2 市场与用户** | 口语问题、产品机制和差异化机会是否真实？ | `market/market_opportunity.md`、`market/voc_analysis.md`、产品价值链、可追溯的 VOC 编码汇总 | 首轮按 30–60 条、至少 2 个平台探索，结论最多 3–5 条；已降级通过。当前证据补强按下方 Stage 2.1 执行，不把首轮样本比例当用户总体比例。 |
| **3 经营与 Driver** | Duolingo 的公开业务发生了什么？ | 可复现分析代码/Notebook、`analysis/business_review.md`、标准化公司级数据表、图表及质量检查记录 | 优先 DAU、MAU、CURR、付费订阅、bookings/revenue 与产品时间线；图表最多 6 张、主要 Driver 最多 3 个。做缺失/重复、单位/时间/口径检查，至少一个对照或替代解释；公司级共时变化只写相关或管理层归因。关键计算和图表可从数据表复现才通过。 |
| **4 量化机会** | 哪些条件下值得投？ | `quant/stage4_final_delivery.md`、`quant/evidence_model.ipynb`、`quant/evidence_assumptions.md`、策略比较、敏感度表与缺口账本 | 最多3策略。只有来源或可核实约束支持参数域才做数值情景；否则保留未知、推导符号盈亏平衡与敏感度，不强填低/基准/高。每个选项给用户、机制、收益、成本、风险、KPI、强度与停止点。方法验证与真实机会量化分开验收；无真实经济数据不选赢家，明确最低补证和下一路线。 |
| **5 决策与实验** | 下一个最值得验证的方案是什么？ | `experiments/test_plan.docx` 与同版 PDF、`experiments/event_spec.csv`、`reports/decision_card.md` | 1 个优先试验、1 个 primary KPI、必要的 guardrails；实验前写假设、处理/对照、随机化单位、样本量/MDE 依据、分析窗口及 Scale / Iterate / Stop。若取得真实数据，再做分组平衡、效果量、置信区间与预设分群分析；否则只交付设计和条件性决策。 |
| **6 展示与复盘** | 别人能否复核并使用结论？ | 8–12 页或同等篇幅的 Decision Book、最多 2 页监控视图、正式数据包、复盘 | 按 `reports/REPORT_SPEC.md` 和 `data/PACKAGE_SPEC.md` 验收：报告含趋势、市场证据、Driver、敏感度与决策图表；每张图可追到表、方法与来源。监控指标预设 Green / Yellow / Red 触发条件与行动；数据包只收录许可允许的内容，文档、代码、数据口径一致。 |

**Stage 2.1 证据补强（已降级收束）**：保留 Stage 2 的探索性结论，集中补足 Video Call 直接相关样本、来源多元性和原始链接核验。去重原始记录争取千级；若平台限制或相关性过低，降为百级并说明原因。数量不单独决定通过；以直接相关样本、可追溯来源、清楚的采样偏差和最多 3 条可测产品假设为收束依据。具体并行任务与唯一验收点见 `docs/STAGE2_EVIDENCE_REFRESH.md`；实际结果以 `docs/STAGE_STATUS.md` 为准。证据已交给 Stage 3，经营诊断已降级通过，可交接 Stage 4；不得用 VOC 比例解释经营变化。

## 五、四个通用 Gate

1. **证据**：关键事实有可追溯来源；计算可复现；未知项不伪装成已知。
2. **业务**：输出能改变对需求、Driver、机会或风险的判断。
3. **决策**：明确下一阶段的选择或待验证条件。
4. **相关性**：仍围绕 Speaking / Video Call 的扩张决策。

任一 Gate 不过：删除无关内容、降低结论强度，或只对阻塞点做一次补充验证；不为追求完整而无限搜集。阶段完成后更新 `docs/STAGE_STATUS.md`，并把长效决策写入 `docs/agent-memory/DECISIONS.md`。

Stage3专项补强后的Stage4最低方法标准见 `analysis/data_quality_report.md` 第8节及 `analysis/stage3_gap_register.csv`。统一估计人群/期间、避免互斥计费状态重复计数；未知规模用归一化、成本/替代联合敏感度与盈亏平衡阈值。参数域内净值或策略排序翻转时，允许收束为“需要先测这个参数”，不得强选赢家。公开完成者学习信号不校准自然采用、留存或收入uplift；情景范围/分位数不是预测置信区间。

Stage3 v1.2收束补充见质量报告第9节和经营复盘第5节：H1/H2限定用户任务与机制，H3检验净值，不构成三个互斥ROI方案。Stage4比较P0现行权益/Max价值边界、P1增量Super、P2有限免费试用；核验现行对照，不能预设目前仅Max可用。固定共同人群/期间，原套餐分层，权重未知不汇总排名；免费人群潜在Max购买分流与原Max实际降级分开。基数桥接和未纳入者敏感度不填功能效果参数。

Stage4当前v2.0已降级收束为证据约束的核算与决策交接，见 `quant/stage4_final_delivery.md`。v1经济D数值退出正式论证和包；当前模型直接使用双臂全员贡献与服务差，实证均值/窗口/币种/N/F均未知，不生成现实收益、阈值数字或排名。Stage5先确认P0、真实增量与实施路线，再选一个可实施问题，不预选P1。独立知情学习研究可以外部开展但不识别权益经营；原Max传播需另设识别。日语L1不代替居住日本、B1.1课程不代替口语水平，当前iOS/原Super身份也未由研究证明。

Stage 5 的决策规则必须在查看任何真实实验结果前固定：**Scale** 需要主要指标达到预设效果且护栏与成本可接受；**Iterate** 用于机制指标有信号但业务效果未达到门槛；**Stop** 用于效果不足、成本越界或护栏恶化。没有真实实验时，这些是未来团队可执行的判断规则，决策卡不得把它们写成已执行结论。

## 六、阶段收束与最终验收

最终交付六类：**有数据和图表支撑的商业决策报告、可复现且可合法共享的分析数据包、可运行的量化模型、对照实验方案及条件性决策卡、最多两页监控视图、复盘与可复用 SOP**。报告主体呈现决策、证据、趋势与风险；细节进入方法和数据附录。Dashboard 只作为必要信息的监控视图，预测只作为敏感度的可选附录。

每次执行按 `Understand → Plan Current Stage → Execute → Validate → Interpret Business Meaning → Stage Review` 走完；`STAGE_TEMPLATE.md` 必须写出发现、证据、商业意义、决策影响、未知项、实际检查和下一步输入。**门槛一旦满足即停止扩展该阶段**。下一步仍在同一主决策下；需要改变主决策或增加新研究主线时，先更新决策简报与本总纲。

最终验收看六件事：真实资料是否支撑事实；数据包能否按说明复现关键表和图；是否找到了与 Speaking 有关的具体商业问题；是否量化了机会或阈值；是否给出可执行的优先试验；是否把实验、监控和复盘连成下一轮决策。没有内部实验结果时，明确写出“尚未验证”，不能为了闭环形式制造结果。
