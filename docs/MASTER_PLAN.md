# 主计划：从证据到决策

## 总体约束

每阶段只回答一个问题。交付物达到 Gate 即收束；新线索先写入 `docs/STAGE_STATUS.md` 的候选待办，不在当前阶段无限展开。每个结论都写明“发现 → 证据 → 商业含义 → 对决策的影响 → 未知项”。可公开分析的事实与只可设计的内部实验必须分开。

| 阶段 | 核心问题 | 最小交付物 | 工作上限与通过门槛 |
|---|---|---|---|
| **0 决策与范围** | 到底要做什么决定？ | `DECISION_BRIEF.md` | 1 个主决策、3 个子问题、最多 3 个候选策略、数据边界清楚。**已通过。** |
| **1 证据与 KPI** | 哪些数字可用、口径是什么？ | 来源登记、指标字典、数据可得性矩阵 | 优先 8–12 个核心指标；每个有来源、时期、单位、定义与限制。关键缺口按 `DATA_POLICY.md` 分类并指定降级方法。公开资料能支撑后续公司级趋势，才进入阶段 2。 |
| **2 市场与用户** | 口语问题和差异化机会是否真实？ | `market/market_opportunity.md`、`market/voc_analysis.md` | 深比最多 3 个直接竞品 + 2 个替代方案；VOC 目标 30–60 条、至少 2 个公开平台，去重、记录采样法、反例与偏差。结论最多 3–5 条，每条需指向可测的产品假设；未达样本目标可交付“探索性”结论并标低信心。 |
| **3 经营与 Driver** | Duolingo 的公开业务发生了什么？ | 可复现分析代码/Notebook、`analysis/business_review.md` | 优先 DAU、MAU、CURR、付费订阅、bookings/revenue 与产品时间线；图表最多 6 张、主要 Driver 最多 3 个。做单位/时间/口径检查，至少一个对照或替代解释；公司级共时变化只写相关或管理层归因。关键计算可复现且结论指向决策才通过。 |
| **4 量化机会** | 哪些条件下值得投？ | `quant/opportunity_model`、`quant/assumptions.md` | 最多 3 个策略、每个低/基准/高 3 情景；分开公布事实参数与假设参数。至少算出一个盈亏平衡阈值，并做关键参数敏感度。未来用户数不做主模型；没有可识别因果参数则只称情景分析。公式、单位和边界检查通过才进入下一阶段。 |
| **5 决策与实验** | 下一个最值得验证的方案是什么？ | `experiments/test_plan.md`、`reports/decision_card.md` | 1 个优先试验、1 个 primary KPI、必要的 guardrails；预先写处理/对照、随机化、样本量依据、分析窗口及 Scale / Iterate / Stop。没有内部原始数据时不做真实效果检验，决策写为条件性的“启动试验/保留/停止”。 |
| **6 展示与复盘** | 别人能否复核并使用结论？ | 简短 Decision Book、最多 2 页监控视图、复盘 | 每一页有来源与决策含义；对外展示真实公开数据与情景模型的标记。文档、代码、数据口径一致；只在真实数据可获取时展示真实产品级监控。 |

## 四个通用 Gate

1. **证据**：关键事实有可追溯来源；计算可复现；未知项不伪装成已知。
2. **业务**：输出能改变对需求、Driver、机会或风险的判断。
3. **决策**：明确下一阶段的选择或待验证条件。
4. **相关性**：仍围绕 Speaking / Video Call 的扩张决策。

任一 Gate 不过：删除无关内容、降低结论强度，或只对阻塞点做一次补充验证；不为追求完整而无限搜集。阶段完成后更新 `docs/STAGE_STATUS.md`，并把长效决策写入 `docs/agent-memory/DECISIONS.md`。

## 最终成果边界

最终交付：**一份可追溯的市场与经营分析、一份可运行的量化模型、一张条件性决策卡、一份可执行的对照实验方案、一份简短管理层报告**。Dashboard 只作为必要信息的监控视图，预测只作为敏感度的可选附录。
