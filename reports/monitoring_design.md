## 2. 设计就绪输入与编辑作用

黄色输入格现在全部为空，空值表示未知。`未来KPI!B5`在该sheet内计算设计就绪状态，首页`B5`引用它；它不读取QA收据，也不计算实验效果。完整行记录、来源与审批需要人工审核，不能凭填写文字自证真实。

| 输入格 | 需填写的内容 | 通过条件与限制 |
|---|---|---|
| D8 | 匹配前测baseline均值，分 | 真实数值≥0；已观察的0可保留，空值仍未知。量表规则先验证。 |
| H8 | 匹配前测SD，分 | 真实数值>0；不能借用完成者研究或别群方差。 |
| D9 | primary MDE，分 | 正数且有power依据。MDE不自动等同业务最小有意义增益。 |
| H9 | 学习窗口HL，天 | 正数、自然任务与延后迁移评估已冻结。 |
| D10 | 实际可执行调用cap，次/账户 | 非负整数、单位与实际权益/计费映射已核。字段不预设或创造试验剂量。 |
| H10 | 同窗账单/预算币种 | 非空文本；不继承USD或用标价代替贡献。 |
| D11 | 完整批准预算上限 | 非负数，须覆盖增量服务、其他及固定投入。0只有获得真实批准且方案确可满足时才有意义。 |
| H11 | 匹配数据及来源定位 | 非空文本引用真实数据版本、来源与核验记录。 |
| D12 | 完整数据契约审核 | 选择“通过/未核/不通过”，不得默认通过。 |
| H12 | 预算审批审核 | 真实批准及完整口径核验后才能选“通过”。 |
| D13 | 实际新增资格审核 | 核实相对真实P0有合法、可实施新增；无增量停止当前公司分支。 |
| H13 | 合法实施权限审核 | 公司/合作方权限及合法延后对照确认；既有购买权益受保护。 |
| D14 | 冻结版本、N和护栏阈值 | 指向冻结预案与完整阈值记录，含业务受益门槛、失访方案、CI与护栏。 |
| H14 | 人群、权益与日期版本 | 明确目标地区/日语L1/英语课程/设备/个人账户/原套餐及实际有效日。 |
| D15 | 成熟经营窗口HB，天 | 正数、账单退款/续订成熟度匹配；与HL分别冻结，不以固定90天替代。 |
| H15 | 分组N、缺测与power来源 | 非空文本，指向匹配方差、分配比、缺测、MDE与N的审定依据；本工作簿没有独立样本量估算结果。 |

**绿色仅表示可提交受限验证审批。** 任一必要字段空白或纯空格，状态保持黄色；四项审核有“不通过”，即使其他字段缺失也显示红色；完整输入但数值/元数据类型无效显示红色；审核仍“未核”显示黄色。零值与缺失分开，不用`IFERROR(...,0)`掩盖缺口。绿色不代表primary通过、真实盈利或Scale。

输入区对应有真实新增资格与实施权限的公司分支C1。已获访问的外部知情参与者研究需要自己的处理和估计对象，不能填成新增权益政策或公司账单效果。

## 3. 未来指标合同与判定

### 六组指标

| 指标 | 分母、定义与未来来源 | 判定与行动 |
|---|---|---|
| 唯一primary：延后未练情境口语迁移总分 | 原随机分配全员，含零使用、取消、切换与配置失败；前测调整组间差，独立盲评、等难度平行任务；来自分配登记、评估计划与盲评记录。失访不记0。 | 95%CI下界达到冻结的最小有意义增益且合理缺测敏感度不翻转才支持学习达标；CI跨门槛/未成熟为黄；充分精度下上界仍低于受益门槛，停止当前处理学习论证。宽区间不等于零效果。 |
| 有效练习机制 | 完成且质量合格的账户/全部原分配资格账户；有效分钟/全部原分配账户；来自资格快照、尝试和有效表达审核事件。 | 达冻结机制目标且质量合格可绿；日志/定义缺失为黄；质量或分配数据失效为红。只诊断采用、零用与失败，不代替primary。 |

未出现有依据的baseline、额度、受益/伤害门槛或预算，因此这些数值不写入成品。CI水平、护栏上限、非劣界与分析窗口须实验前冻结；不在结果出现后改标准。高风险严重事件支持立即暂停，不必等窗口结束。学习/经营必须各自成熟，原组ITT不再乘采用率。

### 从就绪到Scale

绿色设计就绪允许审查受限验证。未来Scale还需：真实primary与缺测敏感度达标、课程/质量护栏通过、完整投入不超真实批准预算、权限及可外推总体通过。盈利准则还需完整双臂贡献/服务费用、同政策曝光的受影响层、真实匹配部署N与新增F；教学投资可按真实预算及学习护栏评价，不能称已盈利。当前所有真实结果未知，不批准Scale。

本页六组KPI中的“未测/黄色”是**静态设计状态**，没有伪装成数据连通或自动告警。编辑准备字段只更新准备状态；不能使未测KPI自动变成成功。未来接入须按`experiments/event_spec.csv`接真实去重事件，保留零活动与缺日志、零能力与缺评估、退款与缺账单的区别，并新增授权刷新流程及实测QA。

## 5. 复现与实际验证

从仓库根目录运行`./scripts/build_monitoring_dashboard.ps1`。构建使用`load_workspace_dependencies`定位的bundle 26.909.12148：bundled Node/Python、`@oai/artifact-tool`、ReportLab、pypdf、Pillow、PDF.js与`@napi-rs/canvas`，未安装新依赖。运行时路径为`%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/`。可写的`reports/generated/monitoring_build/node_modules`是指向bundled依赖的junction，未修改依赖目录。

实际生成链：

1. `scripts/build_monitoring_dashboard.mjs`用artifact-tool创建工作簿、公式、验证下拉、动态条件格式、备注和原生图；测试夹具运行后全部恢复为空，导出XLSX。
2. PowerShell尝试本机Excel COM重算、逐缺字段/边界/配色与图重算。许可限制导致原生保存和PDF导出失败；失败如实记入收据。
3. `scripts/build_monitoring_dashboard.py --prepare`仅补OOXML打印范围/纸张与来源超链接；逐单元格验证值/公式完全保留，不另写数据或图。
4. `mjs --render-saved`重新导入**最终保存的XLSX**，生成每sheet实际PNG；`py --pdf`将这两张完整视图放入2页PDF，并为来源ID保留URL注释。
5. `mjs --render-pdf`用PDF.js与bundled canvas渲染**实际最终PDF**两页，人工目视核对两页中文、表格、图、状态与脚注。

### 已知限制

本机Excel可以实际重算和验证图/条件格式，但`Save`被Office许可过期拒绝，`ExportAsFixedFormat`返回`0x800A03EC`，**两项未通过**。没有改权限、激活或安装软件。XLSX由artifact-tool保存，打印设置由OOXML补齐；未宣称原生Excel打印/PDF验收成功。

PDF是**真实工作簿视图的栅格快照**，可阅读并点击来源，正文不是可搜索/可编辑的PDF文本；可编辑图与字段在XLSX。没有独立拼造数值或伪称Office导出。没有实时事件、账单连接、异常通知、正式实验结果、经济参数或批准预算；真实部署需授权数据、实施权限与重新冻结的执行合同。
